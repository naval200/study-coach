Make a plan

Study Planner makes a learning plan from your goal. It plans only what you do not know yet.

Start

Tell Claude your goal in a few words:

/study-planner move into AI infrastructure in 12 weeks

The planner asks you questions, one or two at a time. It does not write files until you approve the plan.

The main idea

Most plans start with a course and try to finish it. This planner starts with your goal. Then it finds the gap between what you can do now and what the goal needs. The plan covers only that gap.

A good plan feels like "everything I need". It does not feel like "everything there is to learn".

The steps

  1. Goal. You say what you want to be able to do, and by when. Example: get a backend job, build an agent system, pass senior interviews.
  2. Capabilities. The planner changes the goal into things you must be able to do. "Learn Rust" becomes "write and debug production Rust services".
  3. Audit. The planner asks what you have done, built and used. It asks what is rusty and what is new. If it is not sure, it gives you a short test.
  4. Classes. It puts each capability in one class (see the table below).
  5. Gaps. It ranks the gaps. It keeps the 3 to 10 most important ones.
  6. Order. It puts the gaps in order of what depends on what. Topics that do not depend on each other run at the same time.
  7. Resources. It picks resources after it knows the gap. It names the chapter, page or video.
  8. Practice. Use most of the time to do work: build, debug, test, measure, design.
  9. Schedule. It fits the plan to the hours you really have.
  10. Checks. Each module ends with a test of what you can do.
  11. Prune. It reads the plan again and removes what is not needed.

The five classes

ClassMeaningWhat the plan does
A · StrongYou used it in productionSkip it
B · RustyYou learned it, but not latelyShort recap, then 3 to 5 exercises
C · PartialYou know the idea, but you did not build with itTeach the missing parts, with exercises
D · NewYou never learned itA full module: ideas, examples, exercises, a project
E · Not neededThe goal does not need itSkip it, and say why

Each module

Each module in the plan has these parts:

  • Capability: what you can do at the end
  • Why it matters: how it helps the goal
  • Prerequisites: what you need first
  • Learning material: a stack of sources — a main source, a reference, practice, a real-world example
  • Practice: work that looks like real work
  • Done when: a test you can pass or fail
  • Effort: the hours it will take

Good test: "I can design a job queue and explain how it fails." Bad test: "I finished 72% of the course."

Experienced Learner Mode

Use this mode if you already work in the field, or if you did most of this before. Tell the planner. It will then:

  • test before it teaches
  • skip the basics that you already use at work
  • give short refreshers, not full courses
  • give fewer exercises, but more realistic ones
  • make the plan shorter and lighter
Do not relearn the field. Close the gap.

Plans that last

  • The plan uses the hours you kept last time, not the hours you hope for.
  • One day each week has no new material. Use it to review and catch up.
  • A minimum day is a 20-minute version of a day. It still counts.
  • If you miss two days, the plan gets smaller. You do not add hours.
  • New courses and books go to a list for later. They do not go into the plan.
  • A pre-mortem: you say why you might stop. Each reason gets an "if this, then that" rule.

The last part of the plan, "Why this plan", says what the planner assumed, what it put first, and what it skipped. Read it. Change what is wrong.
